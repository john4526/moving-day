# Contacts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Copy each person's saved contacts and labels with Moving Day, and prove it in the scan and the HTML report.

**Architecture:** A `People` wrapper in api.py (same retry and error mapping as Gmail/Calendar), a `FakePeople` in tests/fakes.py, ledger tables for contacts and contact groups, `movingday/contacts.py` for the copy, comparisons in compare.py, new validation checks, and wiring in cli.py (`copy --contacts`, `check` counts).

**Tech Stack:** as the rest of Moving Day (google-api-python-client, pytest, pytest-html).

**Spec:** `docs/design.md`, section "Contacts (added 19 November 2026, approved)".

## Global Constraints

- All constraints in `.superpowers/sdd/2026-11-18-migration-utility/common.md` (package `movingday`) still apply.
- The only destination writes for contacts are create contact, update contact, create contact group, and group membership changes. No contact or group is ever deleted, on either side. The source is only read.
- Ledger stores resource names, etags, states and reason codes only — never names, emails, phones or any contact field.
- Output and report: counts only. New output keys must be added to `safeout.ALLOWED_KEYS`.
- Scopes: source adds `https://www.googleapis.com/auth/contacts.readonly` and `https://www.googleapis.com/auth/contacts.other.readonly`; destination adds `https://www.googleapis.com/auth/contacts`.
- PERSON_FIELDS copied: `names,emailAddresses,phoneNumbers,addresses,organizations,biographies,birthdays,events,urls,relations,nicknames,memberships`.

## Review Focus

1. A contact with no name and only a phone number → copied once, counted.
2. A user label that already exists on the destination with different letter case → reused, not duplicated.
3. Re-run after the source contact was edited → updated, not duplicated; etag mismatch on the destination is retried with the fresh etag.
4. A person with zero contacts → all-zero counts, checks pass.
5. Interrupted copy → resumes without duplicates (pending row recovered by matching the destination listing).

```python
@dataclass
class ContactStats: found: int; contacts_copied: int; contacts_updated: int; contacts_failed: int; labels_created: int; removed_on_source: int

```
Rules: user groups mapped by name case-insensitively (created when absent; system groups `myContacts` and `starred` kept by resourceName, other system groups dropped). Body = present PERSON_FIELDS with memberships translated; strip `metadata`, `resourceName`, `etag`, and per-field `metadata`/`source` sub-keys. New → create (mark pending first, done after). Ledger row exists and source etag changed → update using `get_etag` on the destination; on an etag-mismatch error, re-fetch once and retry. Row whose source contact is gone → counted in `removed_on_source` (never deleted). Pending rows on resume → drop and retry (contacts have no stable dedupe key; ruling: a pending row whose create may have succeeded is re-created — worst case one duplicate, which the compare step reports as extra). Per-contact loop catches ApiError only and records failures. Meta `other_contacts` = `count_other_contacts` (SET). Meta `contacts_removed_on_source` (SET).

Fakes: `FakePeople` with seeding helpers `add_contact(user, person) -> resourceName`, `add_group(user, name) -> resourceName`, `set_other_contacts(user, n)`; etags change on every update; update with a stale etag raises `ApiError("http_400", False)` (real API returns 400 FAILED_PRECONDITION for a stale etag — confirm in rehearsal).

Tests (each named): copies contacts with fields and labels; label case reuse; contact with only a phone; rerun no duplicates; edited source contact updated; stale etag retried once; source only read (calls ⊆ list_contacts, list_groups, count_other_contacts); removed on source counted, never deleted (no delete method exists on People); ledger holds no contact data (dump has no seeded name/email/phone); interrupted copy resumes; empty contacts.

### Task C2: compare, report checks, scan, CLI, docs

**Files:** Modify `movingday/compare.py`, `movingday/cli.py`, `movingday/safeout.py`, `movingday/validation/conftest.py`, `movingday/validation/test_validation.py`, docs; Tests `tests/test_compare.py`, `tests/test_cli.py`, `tests/test_verify.py`, `tests/test_privacy.py`.

**Interfaces:**
```python
# compare.py
@dataclass
class ContactResult: contacts_src: int; contacts_dst: int; contacts_missing: int; labels_src: int; labels_dst: int; label_member_mismatches: int
def compare_contacts(src, dst, ledger, user_key, src_user, dst_user) -> ContactResult
```
- contacts_missing: source contacts with no done ledger row, or whose dst_resource is absent from the destination listing.
- label_member_mismatches: user labels (by name, case-insensitive) whose destination member count is lower than the source's, or which are missing.
- Validation checks (with condition/expected/actual, counts only): `test_contacts_count`, `test_contacts_missing`, `test_contact_labels`; `test_carried_over_notes` adds other contacts not copied and contacts removed on source.
- `copy --contacts`; with no part flags copy all three parts; per-user entry merges ContactStats.
- `check` per user adds `contacts` and `other_contacts`; summary adds `total_contacts`.
- Privacy test extended: marker in a contact's name, email, phone and notes never reaches stdout, stderr, ledger or report.
- Docs: operator-setup scopes lists and commands; rehearsal-checklist items (bulk create limit, starred group, stale-etag error code, other-contacts scope accepted, contacts with photos copy without photos); README command list.
